02 / Method

A security process that can be repeated.

The sequence keeps testing grounded in coverage, application logic, evidence, and useful remediation.

01 / Recon

Map the surface before chasing a finding.

Enumerate subdomains, live hosts, and historical endpoints with tools such as Subfinder, Amass, Gau, and Waybackurls. The goal is coverage first.

02 / Mapping

Understand how the application thinks.

Walk authentication flows, role boundaries, API structure, and the points where user-controlled input reaches business logic.

03 / Testing

Prioritize access control and high-impact paths.

Test IDOR, authentication bypass patterns, session handling, and other OWASP Top 10 classes with manual validation rather than relying on a scanner output alone.

04 / Evidence

Confirm the issue and its actual impact.

Retest every finding so theoretical or non-reproducible behavior does not become a misleading report.

05 / Report

Make the next action obvious.

Write reproduction steps, severity rationale, impact, and concrete mitigation guidance that a developer can use.
