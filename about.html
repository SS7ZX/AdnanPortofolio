About

Two disciplines, one habit.

Information Systems undergraduate with a vocational background in network infrastructure, combining full-stack development with applied web application security testing.

Background

My technical foundation started in vocational high school, studying Computer and Network Engineering, where I ranked first in the National Final Examination and earned a top-score BNSP certification. That gave me subnetting, routing, and Linux administration as a base before I ever wrote a line of application code.

Since then, most of my learning has happened through finishing complete projects rather than isolated exercises: a solo-built payment system, a team-led national competition entry, and a security assessment recognized by my university. I write about the honest scope of each of them, including what I would change, because I think that is more useful to a hiring manager than a polished summary with no edges.

Why security and development together

Building full-stack applications means seeing firsthand where developers cut corners under deadline pressure, which sharpens the security work. Doing security testing means writing application code that is harder to break in the first place. I do not see these as two separate résumé lines; they inform each other on every project.

I am currently a fifth-semester undergraduate, and I frame my experience accordingly: self-directed and internship-based, not large-scale production systems. What I can offer instead is strong fundamentals, a security-first habit formed early, and a track record of finishing what I start.

How I Approach Engineering

Five working principles that show up across every project on this site.

  • Build FirstA working prototype with rough edges beats a perfect plan that never ships.
  • Test Like An OutsiderOnce a feature works, the next question is how someone would abuse it, applied before external review rather than instead of it.
  • Document While BuildingNotes get written during development, not reconstructed afterward, for handoffs and for future me.
  • Prefer Boring SolutionsAuditable beats clever, even when the auditable option costs some flexibility.
  • Name The GapsGo, Supabase Edge Functions, and formal bug bounty methodology are stated as active learning, not overstated as mastery.
